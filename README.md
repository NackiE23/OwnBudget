# OwnBudget

Місячний бюджет замість Excel: вписуєш Salary за місяць, і система розподіляє його за відсотками між категоріями, рахує нерозподілений залишок і «Знято з накопичень» від «Загальні Накопичення» попереднього місяця.

Стек: Django 5.2, Django REST Framework, SQLite, адмінка на [Unfold](https://unfoldadmin.com/). Вимоги описано в [ТЗ: Budget (Django)](https://claude.ai/artifact/1bfjR9bwWo89zyySAzBpA4).

## Запуск локально

```bash
uv sync
cp .env.example .env          # для локальної роботи достатньо DJANGO_DEBUG=1
uv run python manage.py migrate
uv run python manage.py createsuperuser
uv run python manage.py runserver
```

Адмінка відкривається за адресою `http://127.0.0.1:8000/<DJANGO_ADMIN_URL>`, за замовчуванням `/admin/`. Кореневої сторінки немає навмисно.

Імпорт історії з Excel (спершу пробний запуск, він нічого не зберігає):

```bash
uv run python manage.py import_excel "Загальні витрати.xlsx" --dry-run
uv run python manage.py import_excel "Загальні витрати.xlsx"
```

Тести:

```bash
uv run python manage.py test
```

### Правила розрахунку

- Ліміт категорії дорівнює Salary × відсоток. Якщо відсотка немає, ліміт вводиться сумою.
- Нерозподілено = Salary − сума лімітів усіх категорій, крім «Знято з накопичень».
- Якщо всі ліміти задані відсотками, а їхня сума не 100%, адмінка показує попередження.
- «Знято з накопичень» дорівнює відсотку (20% за замовчуванням) від «Загальні Накопичення» попереднього місяця. База — фактична сума («Як Є»), а якщо її ще не внесли, то ліміт. Для першого місяця історії сума лишається ручною.
- Після збереження місяця перераховується й наступний, бо його «Знято» залежить від цього.
- Закритий місяць заморожений: його не перераховують і не редагують, доки його не відкрити знову. Нотатки й позначку змінювати можна.
- ЛПОТТ (ліки + побут + одяг + тварини + транспорт) з 10.26 розбито на п'ять категорій: Ліки, Побут, Одяг, Тварини, Транспорт (міграція 0006). Історія лишається на ЛПОТТ: категорія неактивна й показується лише в місяцях, де вона є.
- Новий місяць створюється порожнім: нічого не копіюється з інших місяців. Він отримує порожні рядки на кожну активну категорію й тип рядка, а відсоток лише той, що заданий у довіднику категорії (зараз 20% у «Знято з накопичень»). Salary та інші дані вносяться протягом місяця.

### Огляд

Головна сторінка, `/<DJANGO_ADMIN_URL>budget/month/overview/`. Рядок на місяць, новіший зверху. Над кожною категорією її назва, під нею «Як Є» і «Ціль» (для накопичень) або «Межа».

- Комірка «Як Є» розфарбована автоматично. Зелений: у межах ±1000 від ліміту. Золотий: краще за план. Червоний: гірше. Для «Загальні Накопичення» краще більше за ціль, для решти категорій (і для «Знято з накопичень») краще менше за межу.
- Відкритий місяць редагується просто в таблиці, кнопкою «Зберегти» в його рядку. Відсотки тут не змінюються: ліміт, що рахується з відсотка, лише показується, а ручний ліміт можна вписати.
- Суми можна вписувати формулами, як в Excel: `=54815+33545`, `=5000+(2111+4363)+(110.11*45.86)`. Дозволені числа, `+ - * /` і дужки. Результат видно під полем одразу під час введення. Формула зберігається поруч із сумою для Salary, рядків доходів і витрат та «Як Є» категорій. Для ліміту й Total expenses зберігається лише результат.
- Якщо суму змінити в обхід формули (форма місяця, API), формула прибирається: вона завжди має давати збережену суму.
- Additional incomes, Savings і Notes це списки записів. Кнопка «Додати запис» відкриває вікно з полями; редагування й видалення запису просять підтвердження. Запис зберігається одразу, без кнопки «Зберегти» рядка, і незбережені зміни в інших полях рядка лишаються.
  - Дохід: сума (можна формулою) і примітка.
  - Savings: сума, валюта, призначення й примітка. Призначення шукається за назвою без урахування регістру; нова назва створює нове призначення.
  - Notes: кожен рядок нотаток окремий запис.
- Рядок і стовпець під курсором підсвічуються, щоб було видно межі комірки.
- Місяць у першому стовпці веде на повну сторінку редагування.
- За замовчуванням показано поточний рік; «Усі роки» це `?year=all`.
- Порожні комірки закритого місяця показують прочерк.

### Імпорт з Excel

- Стовпці шукаються за назвами: лівий блок у рядку з «Month», категорії рядком вище. Кожна категорія займає два стовпці, «Як Є» → `actual` і «Ціль/Межа» → `limit_amount`.
- Значення беруться з кешу формул. Формула `=G13*30%` дає відсоток 30, частка `0.3` теж. Число без формули стає ручним лімітом.
- Формули з числами (`=374+7872+2984`) зберігаються разом із сумою для Salary, рядків витрат і «Як Є». Формули з посиланнями на комірки (`=D17+E17`) не обчислити, тож від них лишається лише сума.
- Food записується в «Як Є» категорії «Їжа», якщо там порожньо. Якщо обидва значення є й вони різні, береться «Як Є», а звіт це показує.
- Savings розбирається порядково: `$` → USD, `€` → EUR, `zl` → PLN, без символу UAH, решта тексту стає призначенням (нові призначення створюються). `2000+4000 облігації` дає один запис на суму, `8000 + $200` два. Рядки з дужками чи `|` стають записами без суми з оригіналом у `raw_text`.
- Additional incomes: кожен рядок комірки стає окремим записом доходу. `3500 мама` дає 3500 і примітку «мама», `1048 + 5408 облігації` дає 6456 і «облігації». Суми в інших валютах у суму не входять (тоді приміткою стає весь рядок), звіт їх перелічує. Міграція 0007 так само розбиває записи, імпортовані раніше одним рядком.
- Ключ запису — місяць. Повторний запуск оновлює відкриті місяці без дублів, закриті пропускає (`--overwrite-closed`, щоб перезаписати). Після імпорту закриваються всі місяці, крім останнього у файлі.
- Після імпорту ліміти перераховуються за правилами застосунку. Якщо результат розходиться з таблицею, звіт це показує.

## Синхронізація з OwnExpenses

Застосунок OwnExpenses надсилає свої операції на сервер. Це лише одна сторона: сервер приймає й показує, нічого не повертає застосунку й поки не впливає на бюджет. В адмінці: «OwnExpenses → Операції» (список, підсумки за місяць і весь час, остання синхронізація), «Журнал синхронізацій» (лічильники кожної відправки за 90 днів), «Пристрої».

### Підключення телефона

1. В адмінці «Пристрої → Додати»: назва телефона. Після збереження сторінка один раз показує токен; у базі лежить лише його SHA-256. Загублений токен замінює дія «Новий токен».
2. У застосунку вписати адресу сервера й токен. Кожен запит має заголовок `Authorization: Bearer <токен>`.
3. `GET /api/expenses/sync/` перевіряє з'єднання: `{"device": "...", "last_sync_at": "...", "server_time": "..."}`, або 401 для хибного токена.

### Відправка: `POST /api/expenses/sync/`

```jsonc
{
  "batch_id": "6f1c…",                 // UUID, новий на кожну відправку; той самий при повторі
  "app_version": "1.4.0",
  "categories": [                      // УСІ категорії телефона, щоразу
    {"id": "uuid", "parent_id": null, "name": "Їжа", "type": "expense", "archived": false, "sort_order": 0},
    {"id": "uuid", "parent_id": "uuid", "name": "Кафе", "type": "expense", "archived": false, "sort_order": 1}
  ],
  "operations": [                      // лише створені чи змінені з минулої успішної відправки
    {"id": "uuid", "type": "expense", "amount_minor": 12550, "category_id": "uuid",
     "date": "2026-11-16", "description": "кава", "created_at": 1763300000000, "updated_at": 1763300000000}
  ],
  "deleted_operations": [              // видалені з минулої успішної відправки
    {"id": "uuid", "deleted_at": 1763300500000}
  ]
}
```

- `id` це UUID, який телефон генерує один раз для запису й не змінює ніколи, зокрема після відновлення з резервної копії. За ним сервер упізнає запис, тож повторна відправка не створює дублів.
- `type`: `expense` або `income`. `amount_minor`: додатна сума в копійках. `date`: календарна дата `YYYY-MM-DD`. Час (`created_at`, `updated_at`, `deleted_at`) в epoch-мілісекундах.
- Категорії приходять повним списком: категорія, якої немає в списку, вважається видаленою. Колір та іконку не надсилати, серверу вони не потрібні. Підкатегорії мають лише один рівень, `parent_id` і `category_id` мають бути в цьому ж списку `categories`.
- Ліміти однієї відправки: 500 категорій, 500 операцій, 1000 видалень. Більше змін телефон шле кількома відправками.
- Усе або нічого: помилка в одній операції скасовує всю відправку.

Відповідь `200`:

```json
{"batch_id": "6f1c…", "duplicate": false, "server_time": "2026-11-16T21:45:12+00:00",
 "categories": {"created": 0, "updated": 1, "deleted": 0, "unchanged": 6, "stale": 0},
 "operations": {"created": 3, "updated": 1, "deleted": 1, "unchanged": 0, "stale": 0}}
```

Помилки: `400` з описом (невалідні дані, відправку не прийнято, повтор нічого не дасть), `401` (токен), `409` (UUID уже належить іншому пристрою), `429` (забагато запитів: понад 240 на годину).

### Правила, що прибирають дублі й зайве

- **Ідемпотентність.** Повтор відправки з тим самим `batch_id` (наприклад, обірвалась відповідь) нічого не змінює й повертає збережений результат із `"duplicate": true`. Телефон може сміливо повторювати відправку, доки не отримає `200`.
- **Новіша версія перемагає.** Операція застосовується, лише якщо її `updated_at` не старший за той, що вже на сервері; інакше вона рахується як `stale`. Запізніла копія не перезапише свіжу.
- **Видалення.** Видалена операція лишається на сервері прихованою (tombstone), тож старша копія не воскресить її. Новіша версія з тим самим `id` (undo на телефоні) відновлює її.
- **Лише зміни.** Телефон позначає записи, змінені після останньої успішної відправки, і шле тільки їх. Після `200` позначки знімаються для тих записів, які не змінились за час відправки.
- Сервер зберігає лише потрібне для перегляду: без кольорів, іконок і налаштувань телефона, а журнал синхронізацій лише як лічильники за 90 днів.

## Рішення щодо відкритих питань ТЗ

| Питання | Рішення |
| --- | --- |
| Total expenses вручну чи з рядків | Зберігається як введено. Поруч показуються сума рядків витрат і розбіжність. Порожнє поле означає суму рядків |
| 01.26: різні значення в P і H | Імпорт бере «Як Є» (P) і показує розбіжність із Food (H) у звіті. Остаточне значення обираєш ти |
| Crypto | Запис накопичень із призначенням «Crypto». У таблиці це гривні («2000 на USDT»), тож валюта UAH, а «на USDT» лишається приміткою |
| Кольори статусу | Колір категорії рахується автоматично (див. «Огляд»). У місяця лишається необов'язкова ручна позначка |
| Notes «-сума …» | Лишаються текстом. Розбір буде в ТЗ історії значних витрат |
| Складні рядки Savings | Імпортуються як запис без суми, оригінал лежить у `raw_text`. Дані не губляться, звіт їх перелічує |
| PLN і USDT | Зберігаються без конвертації, як USD і EUR |
| Salary набрано формулою | Зберігаються і результат (`salary`), і вираз (`salary_expression`) |
